# THE LEGAL TEST (CEO-adopted 2026-07-26 — standing methodology for all AI legal-document products)

Before wiring any AI legal-document product (and at every cited-law change), classify EVERY conclusion the document asserts:

Q1 — Outcome commanded by a bright-line rule applied to ascertainable facts? → TYPE R (Rule). Fully deterministic: Pass-1 derives; polarity-determinism validation applies; model disagreement is a defect; report states conclusion plainly with pinpoint. Examples: 11 CCR § 7150(b) triggers; § 7121(a) cohorts; Civ. Code § 1798.140(d)(1) applicability; state breach-notification counts.

Q2 — Law prescribes factors but leaves outcome to weighing? → TYPE W (Weighing). Pass-1 assembles a FACTOR TABLE (every statutorily required factor, each anchored to ledger fact or registry text; completeness hard-validated; conclusion NOT polarity-validated). Model proposes conclusion with reasoning citing only validated factors (consistency-validated). CALIBRATED RENDERING: firm language only on lopsided factor tables; close balances MUST be disclosed as close with what-would-tip-it stated; flat certainty on a close balance = post-render hard reject. Grading: factor completeness, anchoring, reasoning consistency, calibrated tone — NEVER a single expected outcome. Deterministic expected-answer checks are valid ONLY for Type R. Examples: § 7152(a)(5) benefit/harm weighing; Art 6(1)(f) balancing; Art 35(7)(b) necessity/proportionality; Art 33 risk-to-rights.

Q3 — Conclusion the document should not reach? → TYPE J (Reserved Judgment). Present the completed analysis; pose the decision in customer-question/counsel-voice form. A product boundary, not a capability gap. Examples: ultimate validity verdicts on close balances; anything functioning as contested legal advice.

INFRASTRUCTURE: per product — conclusion inventory _shared/legal-test/<product>-conclusions.ts (every assertable conclusion tagged R/W/J with statutory anchor, versioned) + factor registries _shared/factors/<product>-factors.ts (statutory factor lists for each Type W test, corpus-quoted, pin-tested like verified-authority registries).

FIRST-PASS INVENTORIES (from the 2026-07-26 joint review; refine at each product's build turn): cppa-risk — R: 7150(b)/7121(a)/1798.140(d)(1)/7157; W: 7152(a)(5) weighing (core), severity/likelihood; J: proceed-call on close balance. lia — R: lawfulness edges; W: necessity+balancing (core), reasonable expectations; J: validity verdict on close balance. dpia — R: Art 35(1)/(3) triggers, Art 36 duty; W: 35(7)(b) necessity/proportionality, residual risk; J: risk-acceptability ultimate call. ir — R: state count thresholds, deadlines; W: Art 33 risk-to-rights, Art 34 high-risk. cyber — R: 7120/7121/7123; W: 7122 adequacy. governance — R: presence/absence; W: adequacy characterizations. dpa — R: 28(3)(a)-(h) completeness. admt — R: 7200-7222 obligations, 7001(ddd) scope; W: human-involvement adequacy. registration/biometric — nearly all R.

SEVEN MANDATORY AMENDMENTS to the two-pass design (build-blocking): (1) epistemic_type on every proposition + factor_table structure; (2) validator #6 scoped to Type R only + new Type W validators (factor completeness / anchoring / conclusion-consistency / closeness heuristic recorded); (3) factor registries authored corpus-quoted; (4) Pass-2 Type W templates with firm+hedged variants, deterministic variant selection, what-would-tip-it slot, flat-certainty-on-close-balance = hard reject; (5) conclusion inventory files versioned; (6) grader audit vs inventory — any deterministic check enforcing a Type W outcome as Type R flagged for CEO ruling (measurement correction, not loosening); (7) Type J routed through counsel-voice analysis-then-question templates.

Q4 — CORPUS ENGAGEMENT (CEO-adopted 2026-07-26; standing law, applies to every Type W test AND glossed Type R edges). The corpus is a GUIDE wherever a test or balancing of interests is required, and its engagement is a mandatory role in both passes (and, when engaged, a dedicated additional pass — see Pass G in TWO-PASS-ARCHITECTURE.md §2.6). Four requirements: (a) GUIDANCE MAPPING AUTHORED AT REGISTRY TIME — every factor-registry row (_shared/factors/<product>-factors.ts) carries guidance_refs[] binding interpretive corpus sources deterministically: FSOR commentary (cppa_fsor_commentary and cppa_fsor_callouts) for CPPA tests; EDPB guideline rows for GDPR tests; corpus-quoted, pin-tested, status=final only; runtime lookup is deterministic (no semantic search at render time for authored bindings — semantic layer is candidate-set construction only, resolved to explicit refs before rendering). (b) ANALOGY LAYER GOVERNED — enforcement_actions usage obeys the CEO-adopted eligibility bar: QUOTE-SAFE tier permits verbatim quotes with pinpoint; ROW-GROUNDED tier permits characterizations grounded in the row; INELIGIBLE tier never surfaces (neither quoted nor characterized nor cited). Analogy entries carry the tier explicitly; a render referencing an ineligible row is a hard reject. (c) GAPS ARE INGESTION WORK, NOT IMPROVISATION — a test with no corpus guidance renders on statutory factors alone WITH EXPRESS DISCLOSURE ("guidance on this balance is limited"); the model MUST NOT introduce authority not present in the pre-indexed candidate set. Every empty-by-finding event auto-emits a telemetry record that feeds the T5 ingestion backlog as a ranked work item (rank = product weight × Type W frequency × recency of the empty finding). T5 sequencing, when the program resumes, is standing-input-fed by this queue. (d) FRESHNESS — superseded guidance is excluded at query time (status filter); when T5 lands a new batch in a referenced guidance family (FSOR package or EDPB guideline series), all bindings referencing that family are re-validated (pin re-run, quote re-check, supersession scan). Failed re-validation demotes the binding until re-authored.
